# Deployed protocol compatibility fixtures

`deployed-protocol-34d7cc9.json` freezes command/projection pairs emitted by the already reviewed PR5 `applyRemote` and `apply` models at `34d7cc973bbc9af355f589c146ef30b0f890a13d`. It contains six two/three/four-player remote/shared histories with setup selection, ready/configuration invalidation, leave/rejoin and immutable Begin. Names, identities, command UUIDs and seeds are synthetic protocol samples; no production data or future deck contents are included. Tests substitute a fresh invitation code to avoid collisions in the retained emulator database.

PR3 previews share the canonical production database with later previews. Deploying PR3's original rules would reject these existing histories. The compatibility patch pins the already deployed PR5 rules as a reference (SHA-256 f1911de08b3aeb8c71fce919d41518f340bb9f7ccc704e43fa449092172bcde7) and ships the same policy with equivalent map-comparison fast paths. Those fast paths fix a real Firestore1000-expression rejection of four-player configuration invalidation, without raising any budget or widening write authority. Current policy SHA-256 is1742c465464fab747ac814e1fa2ca557844e205a7ea02df73a7d9d408af2d287 and exercises those wire contracts directly through Firestore, including rejected authority, non-atomic writes, replay/event mutation, competing claims and frozen setup. It adds no later UI, model, reducer or gameplay implementation to PR3. Original foundation security tests remain unchanged.
