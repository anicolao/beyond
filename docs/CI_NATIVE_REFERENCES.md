# Native Linux reference staging

Linux candidates are generated by the existing pinned Playwright workflow. A reference update starts only after local visual acceptance and native Linux image review. Candidate generation, reference staging, independent exact comparison and matching hosted revision are separate gates.

When local storage cannot hold the archive, `.github/linux-reference-review.json` pins its repository, PR, source head, workflow run, artifact ID, SHA-256 digest, executed reference count and visually inspected native image hashes. The `stage-reviewed-linux` label starts the staging workflow on that same-repository PR. It uses the existing pinned Linux image; no additional local runtime or runner endpoint is required.

The runner checks that application/rules/test/capture sources and macOS reference bytes still match the candidate revision. It verifies the entire downloaded archive digest, unique paths, complete executed-reference inventory and reviewed sample hashes. Every native PNG is fully decoded using the existing exact comparator, and its actual dimensions must match the paired reviewed macOS frame. Pixels are never transformed. Inherited obsolete references remain preserved; unexecuted/new archive entries cannot be imported.

The normal staged prompt and E2E policy hooks check the native-reference commit. It is pushed to a temporary review branch, with a downloadable manifest of exact image hashes. This job does not change the PR head or merge anything. After the staged commit is reviewed, the implementation agent advances the intended PR branch to that commit and runs ordinary independent Linux exact comparison without `--update-snapshots`. Preview publication remains independent, and its matching revision and real persistence smoke remain required.
